第 43 课(补):新功能速用 —— v2.1.227(斜杠菜单、/tui 与 rewind、claude-code-action 外部贡献者、过期令牌误判)

说明:本文为 2026-10-13 回溯补生成,内容基于当时(D 前后)的公开报道检索。 📅 2026-08-10 场景还原:你在 GitHub 上开了个"外部贡献者也能 @claude 打标签"的工作流,结果在 GitHub 托管 runner 上每条 Bash 命令都失败;或者你刚 /rewind 回到最开头,切了一下终端渲染器,被撤销的对话又"复活"了;又或者 Max 账号突然弹窗让你为 Fable 开用量额度。08-10 发布的 v2.1.227 是个以修复为主的小版本,恰好把这几处坑填上了。 窗口说明:2026-08-09 至 08-10 之间只有 v2.1.227 一个版本(08-10 发布),内容以修复和体验改进为主,下面讲的是"借这次修复把相关用法用对"。 前置:第 5 课(斜杠命令)、第 10 课(会话管理与 /rewind)、第 12 课(无头模式)。 来源:官方 CHANGELOG · 2.1.227 · Havoptic 08 月版本表

技巧 1(基础):斜杠菜单"匹配字符加粗"——给自定义命令起好找的名字

解决的问题:自定义命令/skill 一多,输入 / 后找不到;旧菜单把匹配字符染色,和"选中行"的蓝色混在一起,看不清哪一行会被执行。

v2.1.227 起:只有选中行是蓝色,你输入的字母在候选名里加粗显示;emoji 和带重音字符的名字也不再被破坏。利用这一点,给命令起"前缀分组 + 连字符分词"的名字,输几个字母就能过滤到:

.claude/skills/ios-build/SKILL.md      →  /ios-build
.claude/skills/ios-testflight/SKILL.md →  /ios-testflight
.claude/skills/img-gen-fal/SKILL.md    →  /img-gen-fal
# 输入 /ios 只剩 ios-* 两条;输入 /fal 可按词首匹配到 img-gen-fal

注意:官方文档写明"按词首匹配并忽略 : _ - 分隔符来高亮首选项"的规则要求 v2.1.236 及以上;在 v2.1.227 上你能看到的是"加粗匹配字符 + 只有选中行标蓝"。打错字时 Enter 会按原文提交并报 Unknown command,用 Tab/方向键选。 📖 官方 CHANGELOG · Commands · 菜单如何匹配

技巧 2(进阶):/rewind 之后再 /tui,撤销不会再"复活"

解决的问题:/rewind 回到首条消息之前(相当于从头来过)后,用 /tui 切换渲染器,旧版本会把已被撤销的对话带回来。

/tui 用于切换终端 UI 渲染器并保留对话重启;/rewind(别名 /checkpoint、/undo)把对话和/或代码回滚到检查点。v2.1.227 修复了二者组合时的"复活"问题,现在可以放心这样用:

/rewind              # 选择回到某条消息之前(可只回滚对话、只回滚代码或两者)
/tui                 # 不带参数:显示当前渲染器
/tui fullscreen      # 切到无闪烁的全屏(alt-screen)渲染器,对话保持当前(已回滚)状态
/tui default         # 切回默认渲染器

延伸:紧接着的 v2.1.228 又修了 "/model 改过后 /tui 把会话退回旧模型" 的问题——切渲染器后用 /status 或 /model 确认一下模型没被改回去。 📖 官方 CHANGELOG · Commands · Checkpointing

技巧 3(进阶):claude-code-action 让无写权限用户触发——在托管 runner 上终于能跑 Bash

解决的问题:想让外部贡献者在 issue 里 @claude 做分诊/打标签,配置了 allowed_non_write_users,但在 GitHub 托管 runner 上所有 Bash 命令都失败(v2.1.227 已修)。

这个参数在官方安全文档里被标为高风险:它绕过了"只有写权限用户能触发"的主防线。所以一定要配齐"最小权限三件套":

# .github/workflows/claude-triage.yml(示意,按官方 security.md 的要求组合)
on:
  issues:
    types: [opened]
permissions:
  issues: write            # 只给打标签需要的权限
jobs:
  triage:
    runs-on: ubuntu-latest
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          github_token: ${{ secrets.GITHUB_TOKEN }}   # 必须;不要用 PAT,也不支持 GitHub App 认证
          allowed_non_write_users: "alice,bob"        # 尽量列名单,"*" 风险最高
          claude_args: '--allowedTools "Bash(gh issue view:*)" "Bash(gh issue edit:*)"'

要点:GITHUB_TOKEN 作用域受 permissions: 限制、随 job 结束失效;静态 PAT 可能被提示注入逐步套出。文档还提到开启该参数时会尽力清理子进程环境里的密钥(CLAUDE_CODE_SUBPROCESS_ENV_SCRUB)——注意:本次读到的是 2026-10 版文档,个别选项可能晚于 v2.1.227 才出现。 📖 官方 CHANGELOG · claude-code-action security.md

技巧 4(高阶):登录令牌过期时的"档位误判"——无头/长驻会话用长期令牌

解决的问题:会话以过期的登录令牌启动时,旧版本评估 feature flag 没带上订阅档位,可能误让 Max 用户"为 Fable 开启用量额度"。v2.1.227 已修,但根因(令牌过期)在无头/CI 场景依然常见。

# 1) 先升级并确认版本
claude update && claude --version      # 应 ≥ 2.1.227

# 2) 交互会话出现异常额度/档位提示:先看状态,再重新登录
#    (在会话内)/status   → 查看账号与订阅信息
#    (在会话内)/login    → 重新登录

# 3) 无头/CI:生成长期 OAuth 令牌,通过环境变量注入
claude setup-token                      # 浏览器授权后打印一年期令牌;它不会自动保存,自己存进密钥管理
export CLAUDE_CODE_OAUTH_TOKEN=...      # CI 里从 secrets 注入,不要写进仓库
claude -p "跑测试并总结失败用例"

相关修复链(同一周):v2.1.225 修了"偶发 401 把长期 CLAUDE_CODE_OAUTH_TOKEN 替换成短期令牌、导致无头会话失效到重启"的问题;v2.1.229 在 /login 成功后会再次提示 CLAUDE_CODE_OAUTH_TOKEN 覆盖警告——环境变量优先于交互登录,排查"为什么登录了还是旧账号"时先 echo $CLAUDE_CODE_OAUTH_TOKEN。另外(据 2026-10 版官方文档):该令牌只能发模型请求,不能建立 Remote Control 或拉取 claude.ai connectors;--bare 模式不读取它。 📖 官方 CHANGELOG · Authentication

今日实操(15 分钟)

  1. 把你最常用的 3 个自定义命令/skill 按"前缀-动作"重命名(如 ios-build、ios-testflight、img-gen-fal)。
  2. 输入 /ios,确认菜单只剩 ios-* 条目且匹配字母加粗;故意打错一个字母,确认 Enter 不会误执行别的命令。
  3. 做一次 /rewind 回到较早的消息,然后 /tui fullscreen 再 /tui default。
  4. 验收:claude --version ≥ 2.1.227;三条命令都能在 ≤ 4 个字母内过滤到;切换渲染器后对话仍停在回滚后的位置、被撤销的内容没有回来,且 /status 显示的模型与切换前一致。
