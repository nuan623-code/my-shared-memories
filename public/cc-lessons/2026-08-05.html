第 7 课:新功能速用——v2.1.221(2026-08-03)

类型:新功能速用 · Claude Code 8月3日发布 v2.1.221,本课挑出对日常工作流影响最大的 4 个新能力,由浅入深讲怎么用。 来源:官方 changelog · What's new · Havoptic 版本摘要

技巧 1(入门):VSCode Focus 视图——长任务只看结论,不看过程刷屏

新版在 VSCode 扩展里加了 Focus 视图:把每一轮的工具调用活动(读文件、跑命令、搜索……)折叠成一条可展开的摘要,只保留一个「正在运行的工具」实时指示灯。跑长任务时界面不再被几十条工具日志刷屏,想追查细节时再点开对应轮次。

可复制操作:

# VSCode 中切换 Focus 视图,两种方式任选:
1) 快捷键 Ctrl+Alt+F
2) 命令面板 (Cmd/Ctrl+Shift+P) → "Claude Code: Toggle Focus view"

适用判断:改动多文件的重构、批量迁移这类「过程很长、你只关心结果」的任务开着 Focus;调试 hooks 或排查它为什么改错文件时关掉,看全量活动。

来源:Claude Code changelog、Havoptic v2.1.221 摘要

技巧 2(基础):/fork 后台会话——主线不断,支线并行试方案

/fork 把当前对话完整复制成一个新的后台会话:支线带着全部上下文去试激进方案,主线继续稳步推进,互不打断。v2.1.221 进一步打通了 /fork 后台会话与更聪明的 /resume、/background 流程(后台会话可在 /resume 列表中找回、固定后保持存活)。

可复制工作流(方案 A/B 并行):

# 主会话:正在按方案 A 实现
/fork
# → 新的后台会话诞生,带全部上下文
# 在 fork 出的会话里:「改用方案 B(事件驱动)重做刚才的模块,完成后总结对比」
# 主会话继续方案 A;之后用 /resume 切回支线看结果,择优合并

来源:What's new · Week 29(/fork 引入)、changelog

技巧 3(进阶):沙箱凭据 mask 模式——真实密钥不再进入沙箱

Linux/WSL 上新增凭据文件「mask」模式:沙箱内的命令读到的是一份哨兵(sentinel)副本——占位假值;只有当请求经过沙箱的出口代理(egress proxy)时,代理才把哨兵替换成真实值发出去。效果:模型和沙箱内任意命令全程接触不到真实密钥,即使 prompt injection 让它「打印环境变量」,拿到的也是假值。

配置入口(具体键名以官方 sandboxing 文档为准):

# 沙箱设置位于 settings.json 的 sandbox 段;
# 凭据文件相关选项新增 "mask" 模式(Linux/WSL)
# 详见:https://code.claude.com/docs/en/sandboxing

适用判断:CI、无头模式 claude -p、以及任何需要携带 API key 跑不可信代码/依赖的场景,优先开 mask;macOS 用户暂以官方文档说明为准(本次发布注明 Linux/WSL)。

来源:changelog、Releasebot 摘要

技巧 4(进阶):Plan Mode × auto 模式——只读命令不再反复弹窗

两处行为变化值得知道:① Plan Mode 配合 auto 模式时,静态分析器无法证明「只读」的 Bash 命令(比如带管道、变量的复杂命令)不再一律弹窗询问,改由 auto 模式的分类器判断安全性——规划阶段的调研命令顺畅很多;② /deep-research 改为只在你手动调用时启动,Claude 不会再自作主张开启深度调研烧配额。

可复制操作:

# 规划复杂任务时:Plan Mode + auto 组合
claude --permission-mode plan
# 会话内按 Shift+Tab 切换权限模式;auto 模式在 /config 或启动配置中开启
# 深度调研现在只能显式触发:
/deep-research 对比这三个方案的社区反馈

判断标准:如果你此前因为「plan 阶段每条 grep/管道命令都要确认」而少用 Plan Mode,这次更新后值得重新把「先 plan 后动工」设为默认习惯(配合第 2 课)。

来源:changelog、Havoptic v2.1.221 摘要
