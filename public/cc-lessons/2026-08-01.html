第 2 课:Plan Mode——先谋后动

每天一个主题、3-4 条由浅入深的技巧。上一课:CLAUDE.md 瘦身术(07-31)。 累积库:claude-code-tips.html

1. Shift+Tab 进入 Plan Mode

大改动前先切到计划模式——Claude 只读代码、做调研、给出方案,不动任何文件;你确认方案后再放行执行。把「先看方案再动手」变成肌肉记忆,能挡掉大部分「改错方向」的浪费。CLI 里连按 Shift+Tab 可在 普通 → auto-accept → plan 三种模式间循环。

来源:Claude Code 官方文档

2. 把 plan 落成文件

复杂任务让它先把方案写进 plan.md(目标、步骤、涉及文件、验证方式),然后逐步执行并勾选:

先进入计划模式,把重构方案写到 plan.md,列出每一步涉及的文件和验证命令,等我确认

长任务中这份文件就是防漂移的锚点,比留在对话里可靠——对话会被压缩,文件不会。

来源:社区最佳实践(iwoszapar)

3. 阶段之间清上下文

执行完一个阶段就 /clear(或用 /compact 压缩保留要点),别让上一阶段的调研噪音污染下一阶段。「计划文件 + 干净上下文」的组合,优于一条塞满历史的超长会话——上下文越干净,单步质量越高。

来源:SmartScope 实践

4. 计划里写明验证方式

让方案自带「怎么证明改对了」:哪条测试、什么命令、预期输出。执行完由它自己跑验证闭环。这与 Cursor Agent Swarm 报告(见 07-31 深度文档)的结论一致:有验证器,放手执行才成立。
