第 10 课:会话管理——/resume、/fork、/rewind 与跨会话消息

2026-08-14 · 主题池:会话管理(--resume、/fork、/rewind、cross-session messaging) 前情提要:第 8 课讲了单会话内的上下文管理(/clear、/compact),今天讲会话之间怎么切换、分叉、回滚与互通。本周(Week 32)刚上线的「跨会话消息」是今天的新功能亮点。

技巧 1(入门):三扇「回到昨天」的门——--continue、--resume 与 /resume

会话(session)是绑定项目目录的持久对话,关掉终端不会丢。回去有三种方式,按精确度递增:

# 直接续上本目录最近一次会话(最快)
claude --continue

# 打开会话选择器,按时间/摘要挑一个
claude --resume

# 会话内切换:打开交互式选择器
> /resume

进阶用法:把 PR 链接粘贴进 /resume,Claude Code 会帮你找到创建这个 PR 的那个会话——review 意见回来时不用再想「这是哪个会话干的」。

注意一个坑:同一个会话在两个终端同时 resume(不 fork)时,两边消息会交错进同一份记录,想并行就用下一条的 /fork。

技巧 2(基础):/rewind 回到过去,/fork 平行宇宙

两个命令解决「改错了想反悔」和「想试另一条路但不想丢当前进度」:

# 回滚:选择回到任意一条历史消息,从那里重新开始
> /rewind
# /rewind 还能把 /clear 之前的对话找回来(v2.1.185+)

# 分叉:把当前对话复制成一个新的后台会话,你继续在原会话干活
> /fork

关键心智:/rewind 产生的新分支会归组在原会话下面,原会话永远不丢;/fork 则是「复制一份去试险」,试成了把改动用 git 带回来,试砸了直接丢弃。两者配合,你几乎不需要「怕改坏」。

📎 官方文档:Manage sessions · What's new Week 26/29

技巧 3(进阶 · 本周新功能):跨会话消息——让会话之间自己传话

Week 32(2026-08-03~08-07)上线:macOS / Linux 上,你的多个 Claude Code 会话可以互发消息。典型场景:会话 A 调试时发现「这个 bug 根因是配置文件里的 X」,它可以直接把这个结论传给正在改配置的会话 B,而不是你复制粘贴当中间人。

实操要点:

# 在会话 A 里直接用自然语言指挥:
> 把「根因是 config/redis.yml 的 timeout 单位写错」这个结论
> 发给正在处理 infra 目录的那个会话

# 收到消息的会话会把它内联显示在对话里(v2.1.220+ 格式已优化)

配合第 3 课的 subagents 理解:subagent 是一个会话内部的分工,跨会话消息是平级会话之间的通信——前者共享父会话的任务目标,后者各自独立、只交换结论,token 上互不污染。

技巧 4(实战):git worktree × 多会话的并行工作流

把前三条组合成一套可复制的并行开发流:

# 1. 为两个任务各开一个 worktree(物理隔离文件)
git worktree add ../proj-featA featA
git worktree add ../proj-fixB  fixB

# 2. 各自目录里起独立会话(会话绑定目录,天然不串)
cd ../proj-featA && claude   # 会话 1:做功能 A
cd ../proj-fixB  && claude   # 会话 2:修 bug B

# 3. 会话 2 修完、发现会影响功能 A 的接口时,
#    用跨会话消息把「接口签名改了」直接通知会话 1

# 4. 第二天回来:
claude --resume   # 挑昨天那两个会话,原地续命

收尾习惯:任务完成后 git worktree remove ../proj-featA,并让长期结论落进 CLAUDE.md(第 1 课)而不是留在会话记忆里——会话是工作台,CLAUDE.md 才是仓库的长期记忆。

📎 官方文档:Manage sessions · Agent SDK sessions(编程式管理)

今日实操(约 10 分钟)

  1. 在常用项目里跑 claude --resume,认一遍自己积攒的会话列表,删掉没用的。
  2. 随便挑一个会话 /fork 一次,体会「原会话不动、分身试险」。
  3. 如果你在 macOS/Linux 上开着两个会话,让其中一个给另一个发条消息,跑通跨会话传话。
  4. 顺手确认:今天(8 月 14 日)起 auto mode 成为新会话默认权限模式,用 /permissions 检查你的 allow/deny 规则是否还符合预期(见第 9 课)。
