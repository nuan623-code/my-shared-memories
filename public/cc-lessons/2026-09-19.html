技巧 1(基础):Ctrl+Enter —— 打断当前回合,一次发出所有排队消息

解决的问题:Claude 在跑长命令时,你回车排队的补充消息要等工具调用结束才送达;想"现在就改方向"只能 Esc 后重打。

# Claude 工作中:输入补充说明 → 回车(进入队列,显示在输入框上方)
# 想立刻生效:
Ctrl+Enter            # 打断当前回合,把所有排队消息一起发出
Ctrl+X 然后 Ctrl+S    # 终端识别不了 Ctrl+Enter 时的备用键(tmux/screen 里常见)

要点(官方 CHANGELOG + 解读实测):已发送和排队中的消息会显示为灰色,直到模型真正收到;只打字不回车不会进入队列;解读作者用 sleep 60 测试,按下 Ctrl+Enter 后不等 60 秒就打断并一起发出。如果仍然等到命令跑完,说明按键没传到终端,改用 Ctrl+X Ctrl+S。 📖 官方 CHANGELOG 2.1.275 · 实测解读

技巧 2(进阶):claude.ai 上启用的技能/插件会同步到终端——需要时关掉

解决的问题:同一账号登录的终端会自动出现你在 claude.ai 启用的技能和插件;共享机器、测试机或 CI 上你可能不想要。

// ~/.claude/settings.json(用户级设置;按需只关其中一个)
{
  "syncClaudeAiSkills": false,
  "syncClaudeAiPlugins": false
}

要点: - 这两个键名来自官方 CHANGELOG;放在哪一级设置文件(用户/项目/受管)由你的需求决定,上面以用户级为例,改完新开会话再用 /plugin、/skills 核对。 - 同版改进:对同步下来的技能文件夹做 Write/Edit 时,结果会提示"改动不会保存回你的账号"并说明怎么保存——别以为在本地改了就同步回网页了。 - 同版还为经 Claude apps gateway 登录加了"保存凭据前确认账号",/status 会显示当前登录账号。

📖 官方 CHANGELOG 2.1.275 · 官方:Settings

技巧 3(进阶 · 安全):npm 插件不再运行安装脚本 + 清查 marketplace URL 里的凭据

解决的问题:插件供应链的两个老坑——npm 包的 postinstall 能在你机器上执行任意代码;带 token 的 git/ssh/marketplace URL 会被原样打印进日志。

v2.1.275 把 npm 来源的插件改为用 npm pack --ignore-scripts 拉取并做完整性校验(破坏性变更:包的 install scripts 不再执行)。同版修复了插件/marketplace 消息、日志和 claude plugin marketplace list 显示 URL 中密码或 token 的问题。

# 1) 升级后先看插件是否还能正常初始化(依赖 postinstall 的会坏)
claude --version          # 确认 >= 2.1.276
/plugin                   # 在会话里查看各插件状态

# 2) 检查你配置过的 marketplace 是否把凭据写在 URL 里(user:token@host 形式)
claude plugin marketplace list
grep -rEn 'https?://[^/@[:space:]]+:[^/@[:space:]]+@' ~/.claude/settings.json ~/.claude/plugins 2>/dev/null | head

插件作者的替代做法(官方 hooks 文档给出的模式):不要依赖安装脚本,而是首次使用时检查依赖、缺了再装,例如在 hook 或 skill 里检测 ${CLAUDE_PLUGIN_DATA}/node_modules 是否存在,不存在就执行 npm install。另外官方文档称通过 marketplace 分发时,Claude Code 会在缓存插件时自动安装符合条件的 Node.js 依赖。 注意:解读文章提醒,用 URL 带凭据的人应回头检查旧日志里是否已经泄露过 token(修复只影响之后的输出)。 📖 官方 CHANGELOG 2.1.275 · Hooks 文档 · Setup 一节 · 解读

技巧 4(高阶):__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__ —— 让自定义系统提示的固定部分全局缓存

解决的问题:用 --system-prompt / --system-prompt-file 跑批量任务时,固定规则 + 每次不同的上下文写在一个字符串里,改一行就让整段系统提示缓存失效。

在提示文件里放单独一行 __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__:上面是固定部分,下面是每次变化的部分。Claude Code 在第一处这样的行把提示切成两块、各自带缓存断点,并删掉这一行本身;v2.1.275 起上面那块全局缓存(与 SDK 的数组写法一致)。

cat > review-prompt.txt <<'TXT'
你是本仓库的 PR 审查助手。规则:
1. 只指出会导致 bug、安全或性能问题的地方
2. 每条给出文件:行号和修改建议
__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__
当前 PR:#1234,作者 alice,改动 12 个文件
TXT

claude -p --system-prompt-file review-prompt.txt "审查当前分支相对 main 的改动"
# 只改最后一行再跑一次,在 /usage 的 Prompt cache 行或 API 返回的
# cache_read_input_tokens 里对比缓存命中

限制(官方文档原文要点):只有直接调用 Claude API 或在 Claude Platform on AWS 上才会切分;Bedrock、Google Cloud、Foundry、LLM 网关,或设置了 CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1 时,整段作为一块发送。需要 Claude Code v2.1.275+;SDK 里优先用数组写法 [静态, SYSTEM_PROMPT_DYNAMIC_BOUNDARY, 动态]。 顺带:走代理/网关的用户别停在 v2.1.275——它引入了一个回归,ANTHROPIC_BASE_URL 指向代理或网关时所有请求报 400 … Input tag 'advisor_20260301',v2.1.276 只修了这一处。 📖 官方:Modifying system prompts · Cache the static part · CHANGELOG 2.1.275 / 2.1.276

今日实操(15 分钟)

  1. claude --version 确认 ≥ 2.1.276(走网关的尤其要确认)。
  2. 让 Claude 执行 sleep 60 && echo done,期间回车排两条消息,再按 Ctrl+Enter(不行就 Ctrl+X Ctrl+S)。
  3. 按技巧 4 写一个带分界行的提示文件,连续跑两次 claude -p,第二次只改分界线以下的一行。
  4. 验收标准:第 2 步不等 60 秒就打断、两条排队消息一起送达;第 3 步第二次运行能看到系统提示的固定部分命中缓存(cache read 明显大于 0);如果你在网关/Bedrock 上看不到切分效果,确认这符合上面的限制说明而不是配置错误。
