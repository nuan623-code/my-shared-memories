iOS 模拟器里跑起来才算做完

iOS 代码「编译通过」离「能用」还差十万八千里——让 Claude 自己在模拟器里装上、点开、跑一遍,验证过了才收工。

本页目录

Claude Code Desktop(macOS)内置 iOS Simulator pane:Claude build、安装、启动或检查你的 app 时,会话旁边会自动打开一块实时流式显示的模拟器画面,Claude 在里面自己点按、读屏、验证改动,你全程可看可插手。这一页讲怎么用它,以及怎么把「模拟器验证通过」变成任务的硬性完成标准。

一句话结论

结论 给 iOS 任务的指令按「跑起来验证」措辞(如「build 后在模拟器里跑一遍 onboarding」),Claude 会自动打开 iOS Simulator pane、装 app、自己 tap 和读屏验证;再把「模拟器里逐屏验证通过 + 汇报所见」写进完成标准,它就不能只靠「编译通过」交差。官方pane 为公共测试版,需 macOS + Claude Code Desktop,Pro/Max/Team 计划(Enterprise 不可用)。

做法步骤

  1. 备齐环境。官方需要:Claude Desktop v1.24012.0+、Mac(iOS 模拟器只在 macOS 上有)、装好 iOS 平台的 Xcode——注意用 Xcode 26.x,pane 还不支持把 Simulator 换成 Device Hub 的 Xcode 27(多版本共存时用 sudo xcode-select -s /Applications/Xcode-26.4.app 指回去)。提示找不到模拟器就跑 xcodebuild -downloadPlatform iOS 装运行时。另外 pane 仅本地会话可用,云端和 SSH 会话摸不到你 Mac 上的模拟器。
  2. 用「跑起来验证」的措辞下任务。官方不需要任何命令或设置,Claude 在模拟器里启动 app 时 pane 自动打开。官方示例措辞:「Build the app and run it in the simulator to check the onboarding flow.」要指定机型就直接说(「run it on the iPhone SE simulator」)。首次使用某台设备时桌面 app 会请求一次授权(按设备记住,之后 tap、输入、截图不再逐次弹窗)。预期:pane 打开,app 装上,Claude 开始自己点。
  3. 把完成标准写死。本站观点光让它「跑一下」还不够,要在任务里列出验证清单:哪些屏、哪些操作、预期看到什么,并要求逐项汇报所见(通用原则见 给它能自己跑的验证)。官方文档本身也建议:改完 bug 或界面后,让 Claude 重新启动 app 验证改动——relaunch 会自动重开 pane。
  4. 人机同屏配合。官方pane 是可交互的:你可以直接点/拖模拟器画面、Cmd+Shift+H 回主屏、Cmd+S 截图 / Cmd+R 录屏(存到桌面)。你和 Claude 操作同一台设备,想让它检查某个特定页面,自己点过去再开口;看到「Claude is using this device」徽章时先别碰,等它操作完。每个会话有自己的设备(最多 4 台),互不串台;Claude 启动的模拟器会在退出/归档/断开 10 分钟后自动关闭。
  5. 认清边界。官方CLI 里没有 pane,Claude 通过 computer use 像人一样操作屏幕上的模拟器(截图对比那套照常可用);真机不支持——想在物理 iPhone 上测,自己用 Xcode 跑,再把所见描述或截图贴给 Claude。隐私上注意:Claude 对设备的截图会发送给 Anthropic,按你的会话保留设置存储,所以别在它用的模拟器里登录真实账号。

可直接抄的 prompt

实现这个功能后,必须在 iOS 模拟器里验证通过才算完成:
1. build app 并在 iPhone 17 模拟器里启动(build 失败先修到能跑)。
2. 按这份清单逐项验证,每项说明你实际看到了什么:
   - 冷启动进入首页,无崩溃、无白屏
   - 新功能入口可见,点进去后界面与需求一致
   - 主流程从头到尾走一遍,每一步的跳转和状态都正常
   - 旋转屏幕 / 回到主屏再切回,状态不丢
3. 发现问题就修复,重新 build、重新在模拟器里走一遍,直到清单全部通过。
4. 结束时汇报:每项的验证结果、修了哪些问题;不接受只有「编译通过」的完成汇报。
