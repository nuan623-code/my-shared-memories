后台跑+手机看进度

长任务不必守在终端前:放后台或云端继续跑,人离开工位后用手机看进度、批权限、给反馈。

本页目录

手机上的 Claude app 不跑代码,它只是会话的客户端。真正要选的是任务跑在哪:本机(Remote Control)还是 Anthropic 云端(cloud session)。判断标准只有一条——电脑关不关。

一句话结论

结论 官方电脑保持开机、任务需要本地文件/工具/MCP → Remote Control:claude remote-control 起会话,手机扫码接管,代码执行始终在本机。电脑要合盖走人、仓库在 GitHub → 云端会话:claude --cloud "任务" 丢上 Anthropic 托管基础设施,手机随时开 Claude app 的 Code 标签页看进度,回工位再 claude --teleport 拉回终端。

做法步骤

  1. 装好手机端。官方下载 iOS/Android 的 Claude app(终端里运行 /mobile 直接出下载二维码),用与 Claude Code 相同的 claude.ai 账号登录,入口在 app 导航的 Code 标签。两条路都要求 claude.ai 订阅登录,API key 不支持。
  2. 本机路:起 Remote Control。官方三种开法:claude remote-control(server 模式,专门等远程连接)、claude --remote-control(正常交互会话同时可远程)、已在会话里则运行 /remote-control 带着当前对话历史接上。server 模式按空格显示二维码,手机一扫直接进。预期看到:终端出现 session URL,手机 Code 列表里该会话带绿点。
  3. 手机上能干什么。官方看对话和 subagent/workflow 的实时进度、发消息接着指挥、传图片(自动下载到本机作为 @ 文件引用)、回答权限确认;终端和手机可交替输入,多端同步。笔记本睡眠或断网,恢复后会话自动重连。
  4. 打开推送。官方终端 /config 里开两个开关:Push when Claude decides(长任务完成、需要你决策时主动推)和 Push when actions required(权限确认、提问时推);也可以直接在 prompt 里写「notify me when the tests finish」。
  5. 本机路的红线。官方本地 claude 进程必须活着——关终端会话就没了;在远程服务器上跑,记得套 tmux/screen 再断 SSH;机器醒着但断网超过约 10 分钟,会话超时退出。
  6. 云端路:电脑要关就用 --cloud。官方claude --cloud "Fix the flaky test in auth.spec.ts" 从当前仓库的 GitHub remote 当前分支开一个云端会话(有本地未推送的 commit 先 push);每条 --cloud 是独立会话,连发几条就是并行跑。CLI 里 /tasks 看进度;手机上打开对应会话可以直接提问、纠偏,甚至从手机发起新任务(Code 标签选 repo 和分支)。首次使用先按官方 web quickstart 连好 GitHub。
  7. 回到工位收工。官方claude --teleport 打开会话选择器,把云端会话连同它的分支拉回本地终端继续改;要求本地 git 状态干净、同一 claude.ai 账号、同一仓库的 checkout。云端会话还能顺手开 auto-fix:在手机上对它说「watch this PR and fix any CI failures or review comments」,CI 挂了或有 review 评论会自动跟进。
  8. 注意额度。官方云端会话与你其它 Claude 用量共享速率限制,并行越多消耗越快;云端 VM 本身不另收费。

可直接抄的 prompt

这个任务预计要跑很久:<任务描述>。
我已经用 /remote-control 连上手机,接下来会离开电脑。请:
1. 把任务拆成清晰的阶段,每完成一个阶段输出一行状态摘要,
   方便我在手机上扫一眼就知道进展;
2. 任务完成或需要我做决定时通知我
   (notify me when the task finishes or needs my decision);
3. 需要权限确认的操作直接发起,我会在手机上批;
   长时间等不到我的批准就先跳过该步骤,继续能做的部分,最后汇总列出跳过了什么。
