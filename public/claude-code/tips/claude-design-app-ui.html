如何结合 Claude Design 开发 app UI

想先把 UI 设计定下来再动手写代码?Claude Design 可以直接把做好的设计打包交接给 Claude Code,不用从截图重新猜。

本页目录

Claude Design 是 Anthropic Labs 2026 年 4 月 17 日发布的官方产品(research preview):左边聊天、右边画布,对话生成设计稿与可交互原型。它和 Claude Code 的正确配合方式不是「截图贴过去」,而是官方内置的交接通道。注意:它不在 code.claude.com 的 Claude Code 文档里,官方信息在 anthropic.com 与 support.claude.com。

一句话结论

结论 在 Claude Design 里对话做出 app UI 原型,用导出菜单的「Handoff to Claude Code」把设计打包交给 Claude Code(本地或 Web)实现——Claude Code 从你已有的设计继续,而不是从零开始。官方官方说明确认:设计可以「handed off to Claude Code, which continues from your existing work instead of starting over」。

做法步骤

  1. 确认资格与入口。官方Claude Design 面向 Pro、Max、Team、Enterprise 订阅(research preview;Enterprise 默认关闭,需管理员开启),由 Claude Opus 4.7 驱动;入口是 claude.ai/design 或 Claude Desktop 侧栏,仅 web 和桌面端可用。预期:打开后看到左聊天、右画布的界面。
  2. 先喂设计系统,再开始画。官方项目会自动继承你组织的设计系统;也可以主动导入——来源支持 GitHub 仓库、设计文件、直接上传,或在 Claude Code 里对本地代码库运行 /design-sync 命令同步。这样后续所有产出会自动套用你的颜色、字体、组件。预期:生成的界面和你现有 app 视觉一致,而不是通用模板风。
  3. 对话做出 UI,再精修。官方用一句话描述要什么(官方示例场景包括:带筛选的 dashboard、移动端 onboarding 流程、多区块 landing page、带条件逻辑的表单),Claude 先出第一版;然后用三种方式迭代:在具体元素上写行内评论、直接改文字、用它生成的调节滑杆实时微调间距/颜色/布局。
  4. 交接给 Claude Code。官方在导出菜单选「Handoff to Claude Code」,有两个选项:「Send to local coding agent」(发给本地 Claude Code)或「Send to Claude Code Web」。设计会被打成一个交接包(handoff bundle),一条指令喂给 Claude Code 即可开工。第三方社区实测:交接包里含组件结构、画布上实际用到的 design token、布局层级和引用素材,并附一份告诉编码代理如何在你的技术栈里还原的 README——把 README 改成含你的栈、文件路径和完成标准,交接质量会明显更高。
  5. 在 Claude Code 里实现并闭环验证。本站观点交接只解决「从设计到代码」,不保证像素级还原。实现后让 Claude 自己截图和设计稿对比找差距(做法见截图对比让它自判 UI;iOS app 再加一道模拟器验证),差异清零才算完。

本站观点如果你没有 Claude Design 资格,退而求其次的官方路径是:把设计稿图片直接拖进 Claude Code 对话让它照着实现(文档明确支持粘贴/拖拽图片),再走截图对比闭环——效果不如带 design token 的交接包,但流程一样能跑通。

可直接抄的 prompt

在 Claude Design 完成「Handoff to Claude Code」后,在 Claude Code 里接着发:

这是从 Claude Design 交接过来的设计包,请按它实现 app UI:
1. 先读交接包里的 README 和 design token,列出你理解的页面结构、组件清单和样式约定,和我确认后再动手。
2. 用本项目现有的技术栈和组件写法实现(不确定就先看 src/ 里的同类组件),不要另起一套样式体系。
3. 颜色、字号、间距一律用交接包里的 token 值,不要目测近似值。
4. 实现完成后逐屏截图,和设计稿对比,列出所有可见差异并逐项修复。
5. 最后汇报:实现了哪些屏、复用/新建了哪些组件、还有哪些差异没消除及原因。
