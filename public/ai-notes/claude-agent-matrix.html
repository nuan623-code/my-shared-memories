🏔️ 2 · 背景:为什么 Anthropic 做出了「一堆」Agent 产品

动机先行:没有这段来龙去脉,后面的产品列表只是名词堆砌。

2023–2024 年,大家用 AI 的方式基本是「聊天框」:你问一句,它答一句。这种模式有个天然的痛点——真实工作不是一问一答。写一份报告要先翻十个文件、查五个网页、整理成初稿再排版;这中间的每一步都要人来「搬运」:把文件内容贴给 AI、把 AI 的回答贴回文档。AI 有脑子,但没有手。

转折点是 2025 年 2 月发布的 Claude Code。它最初是给程序员的命令行工具:让 Claude 直接在你的电脑上读文件、改代码、跑命令、自己看报错再改,循环往复直到任务完成。这套「模型自己动手、自己验证、自己迭代」的执行框架,行业里叫 harness(执行框架/挽具)——第 3 章会讲透这个词。

接下来发生了一件 Anthropic 自己都在官方页面上承认的有趣事情:公司内部的市场、数据等非技术团队开始绕过聊天界面,跑去用 Claude Code,因为它能完成「多步骤的真实工作」,而不只是回答问题。外部用户也出现了同样的模式。这直接催生了 2026 年 1 月的 Cowork——官方内部把它描述为「给其余工作用的 Claude Code」(Claude Code for the rest of your work)。

💡 一句话概括这盘棋
Claude Code 意外验证了一件事:把「会用工具的模型」装进一个好用的执行框架,它就能干活,而不只是聊天。之后 Anthropic 做的所有 agent 产品,本质上都是把这套已验证的执行框架,换上不同的外壳,推向不同的人群。
从 Claude Code 到全家桶:一年多时间里,agent 能力从终端一路铺进浏览器、桌面和 Office。日期来自官方公告与帮助中心(Chrome 预览时间见 Anthropic 新闻稿;Cowork 与 M365 时间见来源清单)。

节奏上还有一个背景值得知道:2026 年 1 月 Anthropic 成立了实验性产品部门 Anthropic Labs(由 Instagram 联合创始人 Mike Krieger 参与主导),Cowork、Claude Design 等消费级产品都从这里孵化。据行业媒体报道,2026 年上半年 Anthropic 保持了大约每两周一次重大发布的节奏,并陆续推出了 Claude Design(设计)、Claude Science(科研)等新入口——本文聚焦你点名的七个,但要知道这个矩阵还在继续扩张。

🧠 3 · 核心概念:看懂矩阵前必须搞清的五个词

后面每个产品的「工具集」都由这些积木拼成,先把积木认全。

🛠️ Harness(执行框架)

是什么

包在模型外面的一整套「运行时装备」:对话与上下文管理(比如上下文快满时自动压缩)、工具调用层、权限控制、会话与文件系统状态、循环控制与错误处理、基础可观测性。模型负责「想」,harness 负责让它能安全地「做」。

为什么重要

裸的 LLM API 只会输出文字。要让它自主干活,就得有人搭这套装备。过去每个团队自己搭,费时且质量参差;Anthropic 的打法是把自家打磨过的 harness 直接产品化——你要么用现成的壳(Code/Cowork/Excel…),要么用 SDK 拿走整套框架自己包壳。

例子

你对 Cowork 说「把这个文件夹里的 PDF 整理成周报」。模型决定「先列出文件 → 逐个读取 → 写初稿」;而实际去执行 ls、读文件、写 docx、出错重试、防止它碰文件夹以外的东西的,全是 harness。

💬 没看懂?换个说法
模型像一位聪明的新员工,harness 就是他的工位:电脑、门禁卡、能用哪些系统的权限单、以及「做错了找谁兜底」的流程。没有工位,再聪明的员工也只能站在走廊里给你口头建议。「harness」原意是马具/挽具——把马的力气变成拉车的功。
Agent 循环
「思考 → 调工具 → 看结果 → 再思考」的自动循环,直到任务完成。这是所有七个产品共同的心跳。
MCP / 连接器
Model Context Protocol,Anthropic 2024 年底发起的开放协议,现已成行业事实标准:让 agent 用统一方式接入外部系统(Slack、Notion、数据库……)。矩阵里所有产品都靠它扩展「能碰到哪些数据」。
Skills
用 Markdown + 脚本打包的「技能包」,教 Claude 某类任务的做法(如做 Excel 模型的规范)。官方文档明确:同一个 Skill 可在 Claude Code、claude.ai、Cowork、Excel/PPT 插件里通用——这是「一套底座」最直观的证据。
Subagent(子代理)
主 agent 把任务拆给多个并行的子 agent 分头执行再汇总。Claude Code 官方更新日志显示,2026 年 6 月起子代理甚至能再派生自己的子代理(链最深 5 层)。
沙箱(Sandbox)
隔离的执行环境,限制 agent 能读写的文件与网络范围。Cowork 在虚拟机级沙箱里跑命令;开发者社区通过逆向发现 macOS 版用的是 Apple 虚拟化框架启动一个定制 Linux(Simon Willison 的分析,社区信息)。

💻 5 · Claude Code:矩阵的原点

GA · 2025.02 发布CLI / 桌面 / Web / IDE迭代频率:每周多个版本

定位与目标用户

面向开发者的自主编码 agent:在你的仓库里读代码、改文件、跑测试、开 PR。但它的实际边界远大于「写代码」——凡是能通过执行代码和命令行完成的事(数据处理、批量文件操作、系统管理)它都能做,这正是它后来「溢出」到非技术人群、催生 Cowork 的原因。

工具集与形态

  • 基础工具:文件读写编辑、Bash、代码检索(grep/glob)、Web 搜索与抓取、MCP 连接器、Skills、subagent、hooks、插件系统。
  • 多形态:终端 CLI 之外,还有桌面 App(2026.04 重设计为多会话并行的「路由工作」模式)、Claude Code on the web(云端跑会话)、VS Code/JetBrains 集成、GitHub Actions。
  • 自主化能力(2026 年官方更新日志确认):/goal 设定完成条件后跨回合自动干到达成(v2.1.139 起);claude agents 统一监控所有会话;auto mode 用后台安全分类器代替逐条权限确认(已下放到 Pro 计划);Routines 云端定时任务;dynamic workflows 让一个会话编排成百个 subagent(Opus 4.8 配套,研究预览);/ultrareview 云端 bug 猎手车队;CLI 里的 computer use(研究预览)。

成熟度与定价

七个产品里最成熟、迭代最快的一个:官方每周发布 What's new 摘要,2026 年 6 月已到 v2.1.19x。定价上不单独收费:包含在 Pro($20/月)与 Max($100 或 $200/月)订阅内,或走 API 按 token 计费;Team 计划中需要高级席位(约 $100–150/座/月,来源为第三方整理,以官方定价页为准)。

🧩 6 · Agent SDK:把 harness 卖给开发者

GAPython / TypeScript2025.09 由 Claude Code SDK 更名
📎 需先理解 Harness(第 3 章)

定位与目标用户

官方文档的表述很直白:Agent SDK 给你的是「驱动 Claude Code 的那一套工具、agent 循环和上下文管理」,以 Python/TypeScript 库的形式开放。目标用户是要把 agent 能力嵌进自己产品或流水线的工程团队:CI/CD 自动化、客服 agent、内部工具、垂直行业应用。

为什么它是矩阵的枢纽

其他六个产品是 Anthropic 自己包好的壳;SDK 是把包壳的权利交给你。官方文档也坦率写明代价:「以运行 Anthropic 的 harness 而非你自己的为代价」——你省下数月基建时间,换来的是接受它的循环与工具约定。社区把这种模式称为 HaaS(Harness as a Service):行业的核心原语正从「LLM API(聊天补全)」转向「Harness API(可定制的 agent 运行时)」。

工具集

  • 内置文件操作、命令执行、Web 搜索等工具,agent 开箱即用;
  • 上下文自动压缩(compaction),长任务不爆上下文;
  • 细粒度权限、会话管理、错误处理、prompt 缓存优化;
  • 可定制系统提示、自定义工具/MCP、subagent(YAML 定义)、hooks。

成熟度、定价与延伸

SDK 本身免费开源,成本是消耗的模型 token(API 计价,如 Opus 4.8;也支持订阅账号认证)。2026 年 4 月起还有云端托管版本 Claude Managed Agents(公测):Anthropic 替你管基础设施、状态、权限与模型升级,适合要审计日志、跨天长任务的企业场景,官方博客称 Notion、Asana、Sentry 已在生产使用。另据多家媒体报道,2026 年 5 月 Anthropic 收购了为其生成官方 SDK 的公司 Stainless——把「agent 连接外部软件的最后一公里」也纳入垂直整合。

🗂️ 7 · Cowork:给不写代码的人的 Claude Code

GA · 2026.04(2026.01 研究预览)macOS / Windows 桌面 App所有付费计划

定位与目标用户

官方产品页的定义:「给它一个目标,Claude 在你的电脑、本地文件和应用上工作,交回一份成品」。目标用户明确是非技术知识工作者:研究员、分析师、运营、法务、财务——每天跟文档、数据、文件打交道,却不想碰终端的人。官方 FAQ 直言其起源:内部非技术团队绕过聊天界面去用 Claude Code,Cowork 就是「同样的能力 + 简化的体验」。

工具集

  • 本地文件夹读写(需授权)、沙箱虚拟机里的 Linux shell、文档产出(docx/xlsx/pptx/pdf 等,配官方 Skills);
  • MCP 连接器与插件市场(含按部门打包的插件)、Skills、并行 subagent、定时任务(scheduled tasks)、可持久刷新的 artifacts;
  • 装了 Chrome 扩展后可接管浏览器做网页任务——矩阵产品互相咬合的典型例子;
  • 写入前询问权限,「重要决定留给人」是官方明确的设计原则。

成熟度与定价

2026-01-12 以研究预览发布(当时仅 Max 订阅可用),4 月起对所有付费计划开放并加入企业管控(角色权限、用量分析等,GA 具体日期来自行业报道,官方页面确认现状为「所有付费计划可用」)。不额外收费,消耗订阅额度。Cowork 团队负责人 2026 年 4 月称发布 12 周后已有数百万人使用(X 帖子,单一来源)。

🗣️ 社区视角(Simon Willison,2026-01)
「我说了很久,Claude Code 是伪装成开发者工具的通用 agent……Cowork 与常规 Claude Code 的差别?不大。它就是套上了不吓人界面、帮你配好了文件沙箱的 Claude Code。我认为这是非常聪明的产品。」——同时他也提醒:让普通用户自己「留意可疑的提示注入迹象」并不现实,安全仍是这类产品的核心疑问(见第 14 章)。

🌐 8 · Claude in Chrome:伸进浏览器的那只手

Beta · 全付费计划Chrome 扩展(侧栏)2025.08 研究预览起步

定位与目标用户

让 Claude 直接在浏览器里干活:读页面、点按钮、填表单、跨标签页操作。它解决的是「没有 API 的系统」这个老大难——很多企业内网、SaaS 后台、政府网站只有网页界面,浏览器 agent 是唯一的自动化通路。它既是独立产品(侧栏对话),也是其他产品的「手」:Cowork 和 Claude Code 都能调用它完成网页环节。

工具集

  • 页面导航、DOM 读取、点击/输入/表单填写、多标签管理、截图与录屏(GIF)、读控制台与网络请求(调试用);
  • 站点级权限控制:默认询问,可按域名放行;敏感操作(如发布、支付类动作)保留人工确认;
  • 与 Claude Code 打通(code.claude.com 有专门文档),前端调试场景:agent 改完代码直接在浏览器里自测。

成熟度与定价

路线很能说明 Anthropic 的「安全渐进」风格:2025 年 8 月以研究预览面向 1000 名 Max 用户试点(官方新闻稿),随后逐步扩大,截至调研时官方帮助中心表述为面向所有付费计划的 beta。官方公开原因是提示注入类攻击的防御仍在完善,GA 前要继续修补(另见:2026 年 7 月有第三方发布说明称其已 GA,与官方帮助中心表述不一致,未能核实,以官方页面为准)。包含在付费订阅内,不单独收费。

📊 9 · Claude for Excel:侧栏里的金融分析师

GA · 2026.05 · 全付费计划Office 加载项Web / Windows / Mac / iPad

定位与目标用户

官方帮助中心定义得很窄也很准:「为大量使用电子表格的专业人士设计,尤其是金融分析与建模」。它不是把表格数据贴给聊天框,而是 agent 直接在打开的工作簿里读单元格、公式和多表结构,并原生地做修改。

工具集(官方帮助中心逐项列出)

  • 读:回答关于工作簿的问题并给出单元格级引用(点击跳到对应格子)、跨多 tab 导航、解释公式链路;
  • 写:在保持公式依赖关系的前提下改假设、建新模型或填模板、修 #REF!/#VALUE!/循环引用等错误,所有改动高亮标注;
  • 原生操作:排序筛选、数据透视表与图表编辑、条件格式、数据验证、打印区域与金融行业格式(如「蓝色输入、黑色公式」的 IB 惯例);
  • 生态复用:支持全部已配置的 MCP 连接器与 Skills(在侧栏输入 / 直接调用)、可设置持久 Instructions;
  • 明确不支持:VBA/宏、Excel 数据表(Data Tables)功能;不建议用于未经人工复核的最终交付物与审计关键计算。

成熟度与定价

2025 年 10 月起小范围预览,2026-05-07 与 Word、PowerPoint 一起在 Microsoft Marketplace 全量 GA(Outlook 同日进入公测,多家媒体交叉印证)。可用性:Pro、Max、Team、Enterprise 全部付费计划,共用订阅额度,不单独收费。企业可经由内部 LLM 网关(Bedrock/Vertex/Azure)使用而无需 Claude 账号。数据方面官方承诺输入输出 30 天内后端删除。

📽️ 10 · Claude for PowerPoint:懂模板的做片人

GA · 2026.05 · 全付费计划Office 加载项Web / Windows / Mac

定位与目标用户

面向「花大量时间做片子的人」——官方示例几乎全是咨询场景(市场规模三页、竞争格局对比、结论先行重排)。它与通用 AI 做 PPT 工具的差异点是模板感知:读取你 deck 的 slide master、版式、字体、配色,在客户或公司现有模板的规范内生成和修改,而不是每次产出一套「AI 风格」的野生设计。

工具集(官方帮助中心)

  • 从模板建新片、对单页做精准修改(不重生成整个 deck)、从自然语言生成整套结构;
  • 把 bullet 变成流程图/示意图与原生可编辑的 PowerPoint 图表(不是贴图);
  • 跨 3–7 页重构叙事线、生成议程页、加过渡页;
  • 连接器 + Skills(如 /deck-check)+ 持久 Instructions(品牌规范类偏好),与 Excel 侧的 Instructions 相互独立;
  • 官方还提供跨 M365 应用的上下文延续:同一工作流在 Excel、PowerPoint、Word、Outlook 之间接力(见「Work across Microsoft 365 apps」文档)。

成熟度与定价

与 Excel 同批:2026-05-07 GA,全付费计划可用,共用额度。局限也一致:聊天记录只存本地浏览器(IndexedDB)、30 天后端删除、Enterprise 之外暂无审计日志;不支持 iPad/Android 版 PowerPoint。此外据行业报道,2026 年 2 月 Opus 4.6 发布时曾以「PowerPoint 侧栏原生集成」作为亮点之一(单一来源,可视为 GA 前的早期形态)。

🔎 11 · Deep Research:会自己查资料的研究员

GA · 2025.04 起claude.ai / 桌面 / 移动端付费计划

定位与目标用户

严格说这不是独立产品,而是 claude.ai 聊天里的 Research 模式(点击输入框「+」开启):你给一个问题,Claude 自主展开多轮、自我修正的搜索——官方描述为「逐次搜索相互递进,自动决定下一步查什么」,通常访问十个以上来源、交叉比对、解决矛盾,最后产出带可核查引用的报告。目标用户最宽:任何要「查清楚一件事」的人。

工具集

  • Web 搜索 + 网页抓取;接入 Google Workspace(邮件、日历、文档)与各类 MCP 连接器后,可把内部资料纳入同一次调研;
  • 产出带引用标注,可逐条点回原文;
  • 开发者侧的对应物:Claude Code 有第一方 deep-research 技能,派出并行 subagent 分头搜索、对论断做对抗式核验后合成带引用的报告(此细节来自社区教程,单一来源)。本文档本身就是这类工作流的产物。

成熟度与定价

2025 年 4 月上线,5 月扩展到移动端与「web + Workspace + 集成」的高级模式,现为 Pro/Max/Team/Enterprise 标配,免费版没有。不单独收费,但官方提醒:一次 Research 检索大量来源,消耗额度比普通对话快。

🏗️ 12 · 布局逻辑:垂直整合 Harness 的思路

把七个产品放回一张图里,战略就显形了。

四层垂直整合:模型 → harness → 共享原语 → 入口。竞品往往只做其中一两层;Anthropic 四层全部自营,且第 2 层还单独作为产品(SDK)出售。

这套打法的三个核心判断

  1. Harness 是新的护城河,不只是模型。同代模型的能力差距在缩小,但「模型 + 自家打磨两年的执行框架」的组合差距在拉大。Anthropic 的工程博客(如《Effective harnesses for long-running agents》)持续输出这套方法论;模型训练时就针对自家 harness 的工具与循环做优化,形成外人难以复制的耦合。
  2. 矩阵按界面切分,不按能力切分。七个产品没有能力上的「高低配」——Excel 插件和 Claude Code 用的是同一批模型、同一套 Skills。切分维度是用户此刻所在的界面。这让 Anthropic 不需要为每个人群重新发明轮子:新入口 ≈ 新壳 + 已有底座,这解释了为何 2026 年能保持高频发布(Design、Science 都是同一模式的延伸)。
  3. 底座本身也是商品:自用 + 外卖两条腿。自家壳覆盖不到的场景,通过 Agent SDK / Managed Agents 让别人来建,token 消耗仍回流 Anthropic;收购 Stainless(SDK 生成商)进一步握住开发者接入的「最后一公里」(据媒体报道)。社区所谓 HaaS——「人人都想成为用户接入智能的那个 harness」——Anthropic 是目前执行得最彻底的一家。
🔗 类比
像苹果做硬件+系统+App Store 的垂直整合,只是对象换成了「智能」。模型是芯片,harness 是操作系统,MCP/Skills/插件市场是 App Store,七个产品是不同形态的终端设备(Mac/iPhone/iPad/Watch)。买任何一台设备,你都进入了同一个生态;开发者想触达这个生态,就得用它的 SDK。

商业模式与竞争语境

收入结构是「订阅 + 企业协议 + API」,官方明确承诺 Claude 产品不放广告(2026 年 2 月还以此为主题投放了 Super Bowl 广告,与 OpenAI 在免费版测试广告形成对照)。据行业通讯报道,Anthropic 的年化收入 2026 年 2 月约 140 亿美元、5 月底约 470 亿美元,同期完成 650 亿美元 H 轮融资、投后估值约 9650 亿美元——这些数字来自单一第三方来源,未经官方逐项确认,仅供量级参考。竞争面上,OpenAI(Codex/ChatGPT Agent)与 Google(Gemini CLI/Antigravity)在各自构建类似的 harness 与入口;Simon Willison 在 Cowork 评测中的判断是「Gemini 和 OpenAI 大概率会跟进这个品类」。

🧭 13 · 选型:什么场景用哪个

同一台引擎,选驾驶舱只看两个问题:你是谁 + 活儿在哪。

⚠️ 14 · 常见坑与限制

官方已知限制与社区高频反馈,分开标注。

🚨 提示注入(Prompt Injection)是全矩阵的头号风险 —— 官方与社区共识
agent 能读外部内容(网页、表格、文件),攻击者就能把恶意指令藏进这些内容里冒充你的指令。官方在 Cowork、Excel、PPT 的文档里都有专节警告,Excel 文档甚至列出了会触发确认弹窗的危险函数清单(WEBSERVICE、INDIRECT、DDE 等),并明确建议:不要对来源不可信的文件/网站使用这些产品。社区批评(Simon Willison)则指出:要求非技术用户「自行留意注入迹象」不现实,在出现标志性安全事件前,这个风险普遍被低估。
  • 额度共享(官方):Excel/PPT/Research 都消耗同一份订阅额度;Research 和并行 subagent 烧额度显著更快,重度用户会撞 Pro 上限。
  • 成熟度不均(官方状态):Chrome 仍是 beta;Claude Code 的 dynamic workflows、computer use 等是研究预览——预览功能的行为和可用性随时会变。
  • Office 插件的边界(官方):Excel 不支持 VBA/宏;两个插件的聊天记录只存本地浏览器、不跨设备同步;Enterprise 之外无审计日志;官方明确不建议用于未复核的最终交付物。
  • Cowork 沙箱 ≠ 绝对安全(社区):文件沙箱限制的是「能碰哪些文件」,但授权范围内的数据配上联网能力,仍构成外泄面(「lethal trifecta」问题)。敏感文件夹别授权。
  • 迭代过快,教程速朽(本调研的直接体会):Claude Code 每周都有行为变化,半年前的教程可能已过时——查任何用法,先看官方 What's new 与 changelog。
