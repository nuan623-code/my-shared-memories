今天有两件事值得看:Anthropic 修订后的 S-1/A 里写了「可能很快达到 RSI 门槛」;Claude Code 出了 2.1.317。Codex 今天没有新版本。下面只放我这次真查到的东西,没查到的直接写没查到。

今日头条

Anthropic 在修订版 S-1/A 里说,它「可能很快」达到自己 RSP 里定义的「AI 带来的显著加速」。 TechCrunch 引用了这份 11 月 2 日公开的文件:Anthropic 说基于内部估计和对未来模型的预期,可能"imminently"满足 Responsible Scaling Policy(RSP,Anthropic 自己的安全承诺文件)里「dramatically accelerated progress attributable to AI」的定义。文件同时说,目前没有任何一个现有模型被认定超过该门槛,并且正在「考虑更新」RSP,以保持人类对前沿模型研发的控制;它也说,即使技术上可行,也不指望能在没有人类有意义监督和理解的情况下,让 Claude 全自动设计、造出下一代前沿模型。文章没给任何数字门槛或时间表。TechCrunch 也提到有人认为 S-1 本身带营销成分,所以「迫在眉睫」这句怎么读,各人有各人的判断。我没读到 S-1/A 原文,这条是二手来源,以原文为准。 来源:TechCrunch(2026-11-02)

Claude Code 2.1.317:子 agent 的 effort 规则变了,Read 的「文件没变」提示没了。 这一版共 87 条改动。对日常使用影响最大的三条:用了不同模型的子 agent / teammate,现在用「那个模型自己保存的 effort」(没有就用它的默认值),不再跟着主会话走;重复读一个没变的文件,会返回完整内容,不再返回 "file unchanged" 占位;在 cloud / 自托管 runner 会话里再跑 claude -p,不再共用外层会话 ID(要旧行为设 CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1)。今天的 Claude 小课逐条讲了。发布日期有出入:一个整理站写 2026-11-02,另一个写 11 月 3 日,我没找到官方 changelog 页上的这一条(官方页抓到的缓存只到 2.1.311),所以日期以 GitHub release 为准。 来源:Claude Code 2.1.317 发布说明(第三方镜像);Classmethod 解读

Agent 技术精选

  • MCP 工具投毒的跨框架实测:arXiv 2611.03555(AISec '26 收录)在 12 个框架、18 个模型、45 个攻击场景上跑了 9,720 个组合,总体攻击成功率 22.9%;结论是「抗性主要看模型,不看框架」,而且没有框架有刻意的防御。今天的深度文档讲它。来源:arXiv(2026-11-02)
  • VeriHarm-Bench:任务做对了,不等于没搞坏东西。 arXiv 2611.03575 把「顺利完成任务但顺手造成意外破坏」定义为 harmful success,用可执行的伤害测试和原任务测试一起跑。摘要说前沿 coding agent 平均任务准确率 95%,但「完成且没触发伤害」的比例平均只有 37%。我只读了摘要。来源:arXiv(2026-11-02)
  • Weight-Space Programming:一篇博客让前沿模型(文中叫 Astra)不经训练,直接读写小网络的权重。最醒目的一个实验:改了 Qwen3.5-0.8B 约 0.016% 的权重(131,072 个),并在允许 50 次前向传播反馈的设置下,MATH-500 从 7.9% 升到 48.1%;反馈次数只有 10 或 25 次时,提升很小。作者自己也说结果早期,对不爱循环的 Gemma 3 270M 没用。这是单人博客,不是同行评审论文。来源:博客
  • Athenahealth 的 athenaPatient MCP server 把患者记录接到 Claude,患者用门户账号授权。来自一份简报站的转述,我没找到厂商原文。来源:Rio Rundown(二手来源)
